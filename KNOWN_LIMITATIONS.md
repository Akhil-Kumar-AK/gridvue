# Known limitations

- Styles/variables: no library publishing; tokens use a Layr-specific JSON (no W3C/Figma format import); no expressions; styles are not editable in place (use "update from selected layer"); a directly edited property of a styled layer is not re-asserted until its style changes (the inspector locks those controls); variable bindings cover the listed properties only (no width/height, per-corner radius, gradient stops). Opacity variables are percentages (0–100). Deleting a variable keeps the value it last resolved to.
- Boolean operations are non-destructive groups drawn by compositing (union uses each child's own fill; subtract/intersect/exclude use the bottom shape's look); there is no flatten-to-vector and no stroke on the combined shape. Masks clip layers above them in the same parent; a text layer cannot be a mask.
- Vectors: no boolean operations, vector networks, SVG import/export; a vector inside an auto-layout FILL/HUG slot is resized without scaling its path; stroke alignment (inside/outside) is centre-only on vectors; pencil output is simplified (Ramer–Douglas–Peucker) and smoothed, not pressure-aware. Layout guides are editor-only (not exported) and do not snap objects.
- Prototyping: the prototype link requires access to the file (no public share links); smart animate matches layers by type + name only and interpolates geometry, opacity, radius, solid/gradient fills and text size (no effects, vector paths or layout changes); "change to" animates whole-frame content; overlays position by preset (no manual position); scrolling frames have no fixed/sticky layers; Move/Push/Slide direction is the direction of motion; destinations deleted after being referenced show as ⚠ missing and are skipped at runtime with a visible message; no video/gamepad/voice triggers.
- **Missing entirely:** multiplayer/presence/comments, version history, Dev Mode/specs/MCP, boolean operations, SVG/PDF export, SVG import, libraries, slides/sites/buzz, all AI features, plugins, code layers, Motion, shaders. Their controls are shown **disabled with an explanatory tooltip**.
- Collaboration-adjacent: role changes are enforced on the next request, not pushed to open sessions. Invitations require an existing account; no email, no share links; no teams.
- Rendering: Canvas 2D (CPU). Group/frame opacity is applied per child (overlapping children show through); shadows on groups are not drawn; text is single-style per node and uses system fonts (no font upload/loading); no image crop; flip is not available (transform model has no mirroring); rotation pivots at the top-left in the model (the UI rotates about the centre).
- Auto layout: no wrap, grid, min/max or constraints. Rotated children use unrotated sizes. Dragging a child inside an auto-layout frame does not show it following the pointer; the slot is picked on drop.
- Components: deleting a layer *inside an instance* is undone by the next sync; no library publishing. Variants: values are free text (no per-property value lists/constraints beyond uniqueness); property bindings are per layer — a new variant copied from another keeps its bindings, but hand-built variants must be bound individually; switching variants carries overrides only for layers with the same name path; instance-swap defaults must be a main component (variants of a set are selectable individually); a variant's own `props` live on the set.
- Snapping covers sibling/parent edges and centres only; no rulers, grids or measurement overlays. Resizing multiple rotated layers is disabled.
- Persistence: SQLite, single process; the brief's PostgreSQL/object storage/workers are not implemented. Whole-document PUT (no deltas); documents are capped at `MAX_DOC_BYTES`.
- `window.__layr` / `__editorCamera` are exposed only in the Vite dev build for tests.
- The benchmark covers the core model only; browser frame-rate/memory numbers are not measured.

- Stroke settings: Dynamic (wiggle) and Brush (four brushes, direction, width profile) are drawn procedurally from the outline and ignore Inside/Outside alignment; they are not editable per point. End points (arrow, triangle, dot) are drawn on lines and open paths only.

- Typography: OpenType feature toggles (numbers, ligatures, stylistic sets, character variants…) are stored and used in the settings preview, but the canvas renderer cannot apply them; only kerning, case and small caps are drawn. Slant is a skew of the glyphs, not a font axis. Text-on-path ignores list, decoration and justify options. Only seven system font families are offered (no uploads or web fonts).

- Figma paste: images are not on Figma's clipboard, so image fills become grey placeholders; auto layout is flattened to fixed positions; flips lose mirroring; radial / angular gradients become linear; inner shadows and background blurs are dropped; component masters arrive as plain frames and instances as frames. The reader was written from Figma's published kiwi schema and tested with a synthetic clipboard, not with a real copy from Figma, so odd payloads may need follow-up (in dev builds `window.__figmaPaste` holds the last decoded message).

- Figma / XD interchange: .fig import reads Figma's published kiwi format and .xd import follows the community-documented JSON layout, but both exporters were only verified by reading their own output back in Layr; they have not been opened in Figma or Adobe XD (Adobe no longer ships XD). Expect to get layers, geometry, text, solid and linear gradient fills, strokes, shadows and images, but not auto layout, components, prototype links, variables, styles, boolean groups (exported as plain groups) or font files. XD export covers one page: top-level frames become artboards, nested frames become groups with a background shape.

## Whiteboard (FigJam-style)
- Single-editor: saves are revision-checked (a second editor gets a conflict banner) but there are **no live cursors, real-time merging, cursor chat, emotes or audio**. Comments and votes are stored on the board; "other people's votes" only appear after they reload.
- Connectors attach to the item's four side midpoints (or the nearest side automatically) and route around nothing — elbows do not avoid other items.
- Images are re-encoded in the browser (max 1600 px) and embedded in the board document (≤ ~3 MB each); there is no separate asset store for boards.
- Export is PNG and a board JSON file; no SVG/PDF. Code blocks use a small built-in highlighter, not a real language grammar.
- Link cards show the URL/host only (no remote page preview or embed).
- Not implemented: Jam AI, widget/plugin marketplace, stickers beyond the emoji stamp set, Mermaid/diagram generation, presentation/spotlight modes, board-level permissions beyond the existing owner/editor/viewer roles, import of real `.fig` FigJam files.
- Verified only in Chromium via Playwright; not compared against real FigJam output.
- Design systems: a design system is a file of type `designsystem` (an ordinary document opened in the normal editor) that a design file can link (Assets → Design system). Using a component copies it, with the variables/styles it is bound to, into a "Design system" page of the design file and creates an instance; **Update** pulls later design-system edits into those copies (properties, added/removed layers and variants, variable values). Limits: one linked design system per file; it is read with the *linking user's* access, so a design file shared with someone who cannot open the design system cannot browse it (already-copied components keep working); there is no publish/version step (edits are live once someone presses Update); edits made to a copied main component inside the design file are overwritten by Update; icons in the default library are text glyphs and shapes, not an icon set.
